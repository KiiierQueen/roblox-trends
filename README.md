# Roblox Trend Tracker

Локальный трекер трендов Роблокса: раз в час собирает онлайн популярных игр,
хранит историю в SQLite, ловит изменения названий/описаний и показывает всё
в веб-дашборде.

Нужен только Python 3.9+ — сторонние библиотеки не требуются.

## Запуск — одна команда

```
python run.py
```

или двойной клик по `start.bat`.

Что произойдёт:
1. Откроется дашборд: http://127.0.0.1:8765/
2. Сразу запустится первый сбор (2–10 минут, зависит от числа игр — запросы идут с паузами).
3. Дальше сбор повторяется каждые 60 минут, пока окно открыто.

Остановить — `Ctrl+C`.

### Посмотреть без ожидания

```
python run.py demo
```

Дашборд на вымышленных играх с историей за 35 дней (в т.ч. сценарий «несколько
игр добавили *Verity* → онлайн вырос»). Реальная база при этом не трогается.

### Другие режимы

| Команда | Что делает |
|---|---|
| `python run.py` | дашборд + сбор раз в час |
| `python run.py collect` | один сбор и выход (для Планировщика заданий) |
| `python run.py serve` | только дашборд, без сбора |
| `python run.py demo` | дашборд на демо-данных |
| `--no-browser`, `--port 9000` | не открывать браузер / другой порт |

### Сбор, даже когда дашборд закрыт (Windows)

Чтобы данные копились без открытого окна, добавьте задачу в Планировщик
(путь замените на свой):

```
schtasks /Create /SC HOURLY /TN "RobloxTrendTracker" /TR "python C:\путь\к\roblox-trends\run.py collect"
```

Дашборд тогда открывайте через `python run.py serve`.

## С телефона

- **Дома (тот же Wi-Fi):** адрес `http://<IP компьютера>:<порт>/` выводится в окне трекера.
  Пароль не нужен. Windows при первом запуске может спросить про доступ Python к сети — разрешите для частных сетей.
- **Откуда угодно:** при `"public_tunnel": true` трекер запускает `tools/cloudflared.exe`
  (официальный Cloudflare quick tunnel) и пишет в окне ссылку вида `https://…trycloudflare.com` и пароль.
  На компьютере дашборд показывает QR-код этой ссылки.
  - Через ссылку без пароля ничего не открывается; пароль хранится в `config.json` (`password`), его можно поменять.
  - После входа телефон помнит вас год. В браузере телефона: «Поделиться → На экран Домой» (iPhone)
    или «⋮ → Добавить на главный экран» (Android).
  - Ссылка меняется при каждом перезапуске трекера; постоянная ссылка требует аккаунта Cloudflare и своего домена.
  - Работает, пока компьютер включён и окно трекера открыто.

## Как пользоваться

**Игры** — таблица: онлайн сейчас, мини-график за 28 дней, рост за 7/14/28 дней
(в % и в разах), визиты, когда вышла последняя версия, когда игра попала в топ.
- По умолчанию сортировка по росту за 14 дней; клик по заголовку — сортировка по колонке.
- Зелёный — рост, красный — падение; чем насыщеннее, тем сильнее.
- Фильтры: «Новые в топе», «С обновлением за 14 дн.», «Мои», минимальный онлайн, поиск
  по названию и описанию.

**Карточка игры** (клик по строке): график онлайна; оранжевые треугольники и
пунктир — изменения названия/описания, серые точки — новые версии без изменения
текста. Клик по отметке прокручивает к обновлению. Ниже — список обновлений с
подсветкой «было → стало» (удалённое красным, добавленное зелёным).

**Тренды**:
- *Новые слова в обновлениях* — слова, которые игры недавно добавили в название
  или описание. Если сразу несколько растущих игр добавили «Verity» — оно будет наверху.
- *Слова быстро растущих игр* — слова, которые у растущих игр встречаются
  заметно чаще, чем у остальных.
- Клик по слову → таблица игр, где оно встречается.

**Лента обновлений** — все изменения названий/описаний за 28 дней по всем играм.

**Мои игры** (кнопка вверху) — ручной список: ссылка на игру, placeId или
`u:<universeId>`. Эти игры отслеживаются всегда, даже если не в топе.

## Как считается рост

Рост за N дней = средний онлайн за последние 24 часа ÷ средний онлайн за сутки
вокруг момента «N дней назад». Суточные средние убирают разницу день/ночь.
Пока трекер не проработал N дней, в колонке стоит «—».

Игры, хоть раз попавшие в топ, продолжают отслеживаться 30 дней, чтобы на
графиках не было дыр.

## Настройки — `config.json`

Создаётся при первом запуске.

| Ключ | По умолчанию | Смысл |
|---|---|---|
| `interval_minutes` | 60 | как часто собирать |
| `request_delay_seconds` | 1.0 | пауза между запросами к API |
| `max_retries` | 5 | повторы при ошибке/429 (с растущей паузой, учитывается `Retry-After`) |
| `explore_max_games` | 300 | сколько игр брать из топов |
| `explore_pages_per_sort` | 3 | сколько страниц каждой подборки листать |
| `manual_games` | [] | ручной список |
| `new_game_days` | 14 | «новая игра» = впервые в топе за N дней |
| `domain` | roblox.com | базовый домен API |
| `port`, `db_path` | 8765, data/tracker.db | порт дашборда и путь к базе |

## Используемые API Роблокса

Публичные, без авторизации:
- `apis.roblox.com/explore-api/v1/get-sorts` и `/get-sort-content` — подборки и топы со страницы «Charts/Discover»;
- `games.roblox.com/v1/games?universeIds=…` — название, описание, онлайн (`playing`), визиты, `updated` (до 50 игр за запрос);
- `apis.roblox.com/universes/v1/places/{placeId}/universe` — ссылка/placeId → universeId;
- `thumbnails.roblox.com/v1/games/icons` — иконки.

## Если в дашборде ошибка «[TITLE UNAVAILABLE]»

Это значит, что Роблокс скрывает данные для вашей сети/региона: API отвечает,
но вместо названий и онлайна — заглушки, а топы приходят пустыми. Трекер такие
ответы не сохраняет и показывает предупреждение.

Нужен сетевой маршрут, через который Роблокс отдаёт данные. Например:
- запускать сбор с включённым VPN;
- или указать прокси через переменную окружения перед запуском
  (`set HTTPS_PROXY=http://адрес:порт` в cmd) — urllib подхватывает её сам;
- поле `domain` в `config.json` позволяет указать другой совместимый адрес API.
